# Silent SSO กับ SchoolOS Users

ครูที่ล็อกอิน SchoolOS อยู่แล้ว เปิด arena → เข้าได้เลยไม่ต้องกรอกรหัสซ้ำ
**ยังไม่ได้ล็อกอิน → ถูกพาไปหน้าแรกของ SchoolOS** (ประตูเข้ามีบานเดียว ดูข้อ 5)

**ไม่ตั้ง `SSO_USERS_BASE` = ปิด SSO ทั้งระบบ** ล็อกอินด้วยรหัสผ่านทำงานครบเหมือนเดิมทุกอย่าง

---

## 1. หลักการ

```
เบราว์เซอร์                       arena server              SchoolOS Users
   |-- GET /users/api/auth/handoff?audience=arena --------->  code (60 วิ ใช้ครั้งเดียว)
   |-- POST /api/auth/sso {code} -->
   |                               |-- POST redeem (X-API-Key) --> ตัวตนผู้ใช้
   |                               |-- ตรวจสิทธิ์เองอีกรอบ แล้วออก session ของเรา
   |<------------------------------|
```

**ทำไมต้องมีโค้ด ไม่รับรหัสผู้ใช้จากเบราว์เซอร์ตรง ๆ:** เบราว์เซอร์เชื่อไม่ได้
ถ้าเชื่อ ใครก็ตามที่รู้รหัสครู (ซึ่งพิมพ์อยู่บนเอกสารทั่วโรงเรียน) `curl` ครั้งเดียวก็เป็น admin ได้
โค้ดขอได้เฉพาะเบราว์เซอร์ที่ถือคุกกี้จริง และแลกเป็นตัวตนได้เฉพาะผู้ถือ API key ของ arena

**prod เป็น same-origin** — nginx เสิร์ฟทั้ง `/users` และ `/arena` ใต้
`https://schoolos.sukhon.ac.th` เดียวกัน จึงไม่ต้องพึ่ง CORS และคุกกี้ถูกส่งไปเอง
พอร์ตหลังบ้าน (`:3002`) ใช้เฉพาะตอน server คุยกับ server เท่านั้น **ห้ามใส่ใน URL ที่เบราว์เซอร์เรียก**

## 2. ไฟล์ที่เกี่ยวข้อง

| ไฟล์ | หน้าที่ |
|---|---|
| `src/lib/sso.ts` | helper กลางตัวเดียวที่คุยกับ Users (handoff / probe / refresh / logout) |
| `src/app/api/auth/sso/config/route.ts` | ส่งค่า config ให้เบราว์เซอร์ตอน runtime |
| `src/app/api/auth/sso/route.ts` | แลกโค้ดเป็น session ของเรา (ถังกันยิงรัวคนละใบกับ login) |
| `src/lib/auth/mapUser.ts` | map สิทธิ์ **ที่เดียว** ใช้ร่วมกันทั้ง SSO และล็อกอินด้วยรหัสผ่าน |
| `src/lib/auth/clientState.ts` | ธง "เพิ่งถูกเตะออก" (มี timestamp) + ธง "ผู้ใช้กดออกเอง" + ธงกันเด้งวนไป portal |
| `src/app/login/LoginForm.tsx` | ประตูเข้าทั้งหมด: ลอง SSO → ไม่ผ่านก็พาไป SchoolOS · ฟอร์มรหัสผ่านเหลือไว้เป็นทางสำรอง |
| `src/components/SessionTimeout.tsx` | คุม session ทั้งของเราและของ SSO พร้อมกัน |

## 3. ค่า environment

ทั้งกลุ่มนี้เป็น env ของ **runtime** ไม่ใช่ `NEXT_PUBLIC_*` โดยเจตนา
→ ย้ายโดเมน / เปลี่ยน audience / ปิด SSO **แก้ .env แล้ว redeploy stack ได้เลย ไม่ต้อง rebuild image**
(`BASE_PATH` เป็นตัวเดียวที่ยังถูก bake ตอน build อยู่)

| ตัวแปร | prod | ความหมาย |
|---|---|---|
| `SSO_USERS_BASE` | `https://schoolos.sukhon.ac.th/users` | ที่อยู่ Users **ในสายตาเบราว์เซอร์** · ว่าง = ปิด SSO |
| `SSO_AUDIENCE` | `arena` | ต้องตรงกับ `handoffAudience` ของ API key เป๊ะ |
| `SSO_PORTAL_URL` | `https://schoolos.sukhon.ac.th/` | หน้าแรก SchoolOS — ปลายทางเมื่อ session จบ · **ใส่ URL เต็ม** ไม่ใช่ `/` (ค่านี้ถูกส่งเป็น `next=` ให้ Users ตอน logout ด้วย) |
| `SSO_API_BASE` | (ว่าง) | ที่อยู่ Users **ในสายตา server** · ว่าง = ใช้ `SCHOOLOS_API_BASE` |
| `SESSION_IDLE_MINUTES` | 15 | ต้อง **≤** `SESSION_IDLE_MINUTES` ของ Users เสมอ |
| `SESSION_ABSOLUTE_MINUTES` | 480 | เพดานสัมบูรณ์ ให้ตรงกับฝั่ง SchoolOS |

## 4. สิ่งที่ต้องพร้อมฝั่ง SchoolOS

API key ของ arena ต้องมี scope `auth:handoff` **และ** ตั้งช่อง "ระบบปลายทาง (audience)" = `arena`
(มี scope แต่ไม่ตั้ง audience = แลกโค้ดไม่ได้เลย)

```bash
curl -H "X-API-Key: sk_live_..." http://192.168.200.56:3002/api/public/v1/me
# ต้องเห็น auth:handoff ใน scopes และ "handoffAudience": "arena"
```

prod ไม่ต้องขออะไรเรื่อง origin — same-origin อยู่แล้ว
จะต้องขอเพิ่ม origin ใน `SSO_ALLOWED_ORIGINS` ก็เฉพาะตอนอยากเทส SSO ตอน dev (exact match ห้ามมี `/` ปิดท้าย)

ตอนคอนเทนเนอร์สตาร์ต `docker-entrypoint.sh` จะเช็คให้เองแล้ว **เตือน** ถ้าไม่ครบ (ไม่ล้ม —
SSO ขาดอะไรไปก็แค่ไม่ทำงาน ระบบต้องขึ้นได้ตามปกติ)

## 5. นโยบาย session

**ขาเข้า — ไม่มี session ของ arena = ไปเข้าสู่ระบบที่ SchoolOS เท่านั้น**
(ก่อนหน้านี้ขาเข้ากับขาออกไม่ตรงกัน: ออกไป SchoolOS แต่พอกลับเข้ามาเจอฟอร์มของ arena ให้กรอกซ้ำ)
ตัดสินใจที่ `src/app/login/LoginForm.tsx` ที่เดียว ตามลำดับนี้

| เจอสถานการณ์ | หน้า `/login` ทำอะไร |
|---|---|
| ล็อกอิน SchoolOS อยู่ | แลก handoff เงียบ ๆ → เข้าระบบเลย (ผู้ใช้แทบไม่เห็นหน้านี้) |
| ยังไม่ได้ล็อกอิน / ขอโค้ดไม่ผ่าน | `location.assign(SSO_PORTAL_URL)` |
| เพิ่งเด้งไป portal มาเมื่อกี้ (`bouncedRecently`) | หยุด ให้กดปุ่ม "เข้าสู่ระบบอีกครั้ง" เอง — **กันลูป arena ↔ portal** |
| เพิ่งถูกเตะเพราะ idle (`kickedRecently`) | หยุดให้กดปุ่มเอง (เด้งอัตโนมัติ = วนไป-กลับจนครบช่วง idle) |
| ล็อกอิน SchoolOS อยู่ แต่เข้า arena ไม่ได้ (พ้นสภาพ/ไม่อยู่ในทะเบียน) | หยุด + แสดงเหตุผลจาก server · **ห้ามเด้ง** portal จะส่งกลับมาทันที = วนไม่จบ |
| ติดต่อ Users ไม่ได้ / SSO ปิด / เปิดด้วย `?local=1` | ฟอร์มรหัสผ่าน (ทางเข้าสำรองของ admin local วันที่ SchoolOS ล่ม) |

- **idle 15 นาที** · เพดาน 8 ชม. · ต่ออายุอัตโนมัติระหว่างที่ยังใช้งานอยู่จริง
- ต่ออายุ **เฉพาะเมื่อมีการขยับจริง** (`pointerdown / keydown / wheel / touchstart / scroll`)
  — ห้ามนับ `mousemove` เพราะเมาส์สะเทือนบนโต๊ะก็ต่ออายุได้ = เท่ากับไม่มี timeout
- ต่ออายุ session ของ **Users** ทุก 10 นาทีด้วย เพราะ Users ไม่นับการใช้งานในระบบเราเป็น activity (จงใจ)
  ไม่ต่อให้ = ครูที่ทำงานอยู่แท้ ๆ หลุดจาก SchoolOS เงียบ ๆ
- session จบ → ส่งผู้ใช้ไป **หน้าแรกของ SchoolOS เสมอ** ทั้งกดออกเองและหมดเวลา
  (ผู้ใช้ได้รับคำเตือนล่วงหน้า 2 นาทีในกล่องข้อความอยู่แล้ว) · ตัดสินใจที่เดียวคือ `ssoExitUrl()`
  ใน `lib/sso.ts` — ตกกลับมาที่ `/login` ของเราเฉพาะตอน **SSO ปิดอยู่หรืออ่าน config ไม่ได้**
- ปุ่มออกจากระบบ → ออกจาก SchoolOS ด้วย ไม่งั้น SSO พากลับเข้ามาเอง = ล็อกเอาต์ไม่ได้จริงบนเครื่องส่วนกลาง
  · session ที่ **ไม่ได้** ผูก SSO (admin local / ล็อกอินด้วยรหัสผ่าน) ไปหน้าแรก SchoolOS เหมือนกัน
  แต่ **ไม่** ยิง logout ของ Users เพราะจะไปเตะ session ของคนอื่นที่ค้างอยู่บนเบราว์เซอร์เครื่องเดียวกัน

## 6. กับดักที่แก้ไว้แล้วในโค้ด (อย่ารื้อ)

| # | เรื่อง | ทำไม |
|---|---|---|
| 1 | ธง "เพิ่งถูกเตะออก" เก็บเป็น **timestamp** ไม่ใช่ธงเปล่า | ธงเปล่าที่ล้างตอนล็อกอินสำเร็จเท่านั้น → เบราว์เซอร์ที่เคยหมดเวลาสักครั้งจะไม่ได้ SSO อีกเลยข้ามวัน อาการที่เห็นคือ "บางเครื่องเข้าเอง บางเครื่องไม่เข้า" |
| 2 | หน้า login ลอง SSO ใหม่ตอน `visibilitychange` / `focus` | SPA ไม่โหลดหน้าใหม่ → logout แล้วไปล็อกอิน SchoolOS อีกแท็บ กลับมาแท็บเดิมจะไม่มีอะไรลองใหม่ให้เลย · เว้นระยะ 15 วิ (Users จำกัด 10 โค้ด/นาที) และห้ามแย่งถ้าผู้ใช้เริ่มพิมพ์แล้ว |
| 3 | ข้าม 401 ถ้าผู้ใช้กดออกเอง (`beginSignOut`) | request ที่ค้างในท่อตอบ 401 หลังล้าง session → หน้า login ขึ้นข้อความผิดบริบท แถม SSO โดนบล็อกต่ออีกช่วง |
| 4 | หน้า login เด้งไป portal ได้ **เฉพาะหลังลอง SSO แล้วไม่ผ่าน** เท่านั้น ห้ามเด้งตั้งแต่ middleware/ตอน render | ฝั่ง server ไม่มีทางรู้ว่าเบราว์เซอร์นี้มีคุกกี้ของ Users อยู่ไหม (httpOnly คนละ origin) → เด้งไปทั้งที่ล็อกอินอยู่แล้ว แล้ว portal ก็ส่งกลับมา = วนไม่รู้จบ |
| 4b | เด้งได้ 1 ครั้งต่อ 1 นาที (`markPortalBounce` / `bouncedRecently` ใน sessionStorage) + `?local=1` เปิดฟอร์มได้เสมอ | ตัวกันลูปด่านสุดท้าย และ admin local (ทางเข้าสำรองตอน SchoolOS ล่ม) ต้องมีทางเข้าฟอร์มเสมอ |
| 5 | ถังกันยิงรัวของ `/api/auth/sso` แยกจาก `/api/auth/login` | หน้า login ยิง SSO เองทุกครั้งที่เปิด ถ้าถังเดียวกัน แค่รีเฟรชไม่กี่ครั้งผู้ใช้ก็ล็อกการล็อกอินด้วยรหัสผ่านของตัวเอง |
| 6 | `used_code` = บั๊กฝั่งเรา ขึ้น log ระดับ error และ **ห้าม retry ด้วยโค้ดเดิม** | โค้ดใช้ได้ครั้งเดียว ต้องขอใหม่เสมอ |
| 7 | ตรวจสิทธิ์เองอีกรอบหลัง redeem (`fetchActiveTeacher` / `fetchActiveStudent`) | payload จาก handoff ไม่มี `active`/`status` และ role มีแค่ `teacher\|student` → คนที่ลาออก/จบไปแล้วจะเข้าได้ถ้าไม่ตรวจ |
| 8 | entrypoint **เตือน** ไม่ใช่ `exit 1` เมื่อ key/scope ไม่ครบ | เคยตั้งเป็นตายทันทีแล้ว SchoolOS ล่มชั่วคราว = arena restart วนไม่จบ |
| 9 | `SSO_PORTAL_URL` ถูกทำเป็น **URL เต็ม** เสมอก่อนใช้ (`portalUrl()` ใน `lib/env.ts`) | Users resolve `next` ที่เป็น path ล้วนด้วย base ของตัวเอง ซึ่งตั้งไว้เป็น `https://0.0.0.0:3002` → กดออกจากระบบแล้วไปโผล่หน้า "can't reach this page" · วัดของจริง: `next=/` → `https://0.0.0.0:3002/`, `next=<URL เต็ม>` → ถูกต้อง, **ไม่ใส่ `next` เลย** → ถูกต้อง |

## 7. Checklist ก่อนบอกว่าเสร็จ

- [ ] ล็อกอิน SchoolOS อยู่ → เปิด arena → เข้าได้เลย ไม่เห็นหน้า login
- [ ] ยังไม่ล็อกอิน → ถูกพาไปหน้าแรก SchoolOS ทันที (ไม่เห็นฟอร์มของ arena เลย)
- [ ] ที่หน้าแรก SchoolOS กดไอคอน arena กลับมาทั้งที่ยังไม่ล็อกอิน → **ไม่เด้งวน** หยุดที่ปุ่ม "เข้าสู่ระบบอีกครั้ง"
- [ ] กดออกจากระบบ → ไปล็อกอิน SchoolOS ใหม่ → สลับกลับมาแท็บเดิม → เข้าได้เองโดยไม่ต้อง F5
- [ ] เปิดทิ้งไว้ไม่แตะเลย → หลุดตาม idle แล้วถูกส่งไปหน้าแรกของ SchoolOS
- [ ] นั่งใช้งานไปเรื่อย ๆ จน token ควรหมดอายุ → ไม่ถูกเตะออก
      (ลองเร็ว ๆ ด้วย `SESSION_ABSOLUTE_MINUTES=20` ชั่วคราว)
- [ ] แท็บที่เปิดค้างไว้เฉย ๆ → ไม่ถูกต่ออายุ ต้องหลุดตามกำหนด
- [ ] คนที่ถูกถอดสิทธิ์ / จบไปแล้ว → เข้าทาง SSO ไม่ได้ เหมือนทางรหัสผ่าน
- [ ] ยิงโค้ดเดิมซ้ำ → ได้ `used_code` และระบบไม่ retry ด้วยโค้ดเดิม
- [ ] `grep -r sk_live_ .next/static` ต้องไม่เจออะไร (API key ห้ามหลุดไป bundle ฝั่ง client)
- [ ] เปิด `/arena/login?local=1` ตรง ๆ ได้ฟอร์มเสมอ (ทางเข้าสำรองของ admin local ตอน SchoolOS ล่ม)

## 8. กับดักตอน deploy (ทำ prod ล่มมาแล้ว 2 รอบ)

1. **404 ทั้งเว็บ** = `BASE_PATH` ว่างตอน build → asset กลายเป็น `/_next/...`
   compose ใช้ `${BASE_PATH-/arena}` ซึ่ง fallback เฉพาะตอน "ไม่มีตัวแปร" — **มีตัวแปรแต่ค่าว่างจะได้ค่าว่างจริง**
   ต้องเขียน `BASE_PATH=/arena` ให้ชัด · เช็คเร็ว: `curl .../arena | grep -c '/arena/_next'` ต้อง > 0
2. **502 Bad Gateway** = คอนเทนเนอร์ไม่ขึ้นเลย (คนละเรื่องกับ 404 ซึ่งเป็นเรื่อง path)
   สาเหตุที่เจอ: `.env` มี `JWT_SECRET=` ว่าง → compose interpolate ไม่ผ่าน → stack ไม่ deploy
3. ตัวแปร `SSO_*` **ไม่** ถูก bake ตอน build — แก้แล้ว redeploy พอ ไม่ต้อง rebuild
   (ต่างจาก `BASE_PATH` ที่ต้อง rebuild เสมอ)
4. ห้ามส่งไฟล์ `.env` ที่ "สตาร์ตไม่ได้ถ้าไม่เติมค่า" ให้คนเอาไปก็อป — ทำ prod ล่มมาแล้ว
   ตัวแปร `SSO_*` ทุกตัวจึงมี default ที่ปลอดภัย (ไม่ตั้ง = ปิด SSO ไม่ใช่สตาร์ตไม่ขึ้น)

บรรทัดแรกของ log ตอนคอนเทนเนอร์สตาร์ตจะพิมพ์ `BASE_PATH`, ปลายทาง API และสถานะ SSO ให้แล้ว
— ดูจากตรงนั้นก่อนเสมอเวลา prod มีปัญหาหลัง deploy
